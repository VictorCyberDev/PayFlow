## Open launch blockers (internally controllable)

1. **Authenticated enterprise approvals:** evaluateApprovalEvidence assumes already-authenticated server records; its evidence string length is not signer/role verification. Build a trusted approval ingestion/store, bind signer and active role to action digest, and verify revocation before use. Never expose this helper directly to model/request data.
2. **Hosted protocol composition:** OAuth JWT verification is not an OAuth authorization service. Commission code+PKCE/resource/redirect/client policy and revocation. Bind verified tenant/subject to actual durable financial services. The runnable CLI is explicitly local fake-rail Sandbox only.
3. **A2A delegation:** the wire profile validates a presented child against trusted parent, but does not yet apply all child constraints to the exact action. Do not use it for delegated financial execution. Implement durable replay and required task semantics, and validate with a public independent implementation/TCK.
4. **Distributed controls:** in-memory rate/replay state is for local tests. Implement atomic distributed limits, retention and operator controls before multi-instance exposure. Bound all remote issuer/provider operations and add operational monitoring.
5. **Real providers:** M26/M27 remain fake substitutes. Implement genuine adapters and provider-specific UNKNOWN/idempotency/reconciliation/Proof acceptance. A provider reference string alone is not capture truth.
6. **Multi-region/transparency:** conflict/lease/hash-chain helpers do not provide replicated state, fencing, signed published checkpoints or independent monitors.
7. **Privacy and sharing:** finalize retention/deletion workflow, minimized public Proof sharing, data-controller disclosure and private vulnerability intake. Legal drafts are not reviewed agreements.
8. **Full acceptance:** native PostgreSQL fresh-DB and authenticated browser E2E were unavailable in this workspace. Required GitHub CI must be checked on the final exact head. Coverage excluding skipped DB paths must not be presented as full coverage.
9. **Public distribution policy:** official OpenAI plugin guidelines currently prohibit execution of money transfers, crypto transfers and investment trades; physical-goods checkout has separate requirements. Review PayFlow's public tool profile against these rules before submission. Do not expose payout/transfer functionality through a public plugin or disguise it as verification. The current five-tool local surface does not itself execute a provider transfer.
10. **MCP completeness:** exact output schemas, full latest-version conformance, deployed auth/abuse testing remain review tasks. The implementation does not claim every MCP feature.

## Validation limits

Unit, protocol, console and static public-browser checks provide local evidence only. No real model, second rail, merchant, partner, auditor or certification was created. A green CI run cannot close these operational/external findings. Zero npm production audit findings is a dependency snapshot, not an application security verdict.
