# Cost model

**HYPOTHESIS - NOT VALIDATED.** This is a calculator over an explicit input table, implemented in [`scripts/cost-model.ts`](../../scripts/cost-model.ts) and tested in `tests/m15-cost-model.test.ts`. It is deterministic and pure (no I/O). It models cost to serve, not price and not demand. PayFlow has no customers and no production traffic, so **usage-shape inputs are estimates, not measurements**.

Run: `node --import tsx scripts/cost-model.ts --inputs | --per-thousand | --margin`.

## Rules for inputs

Every unit cost is exactly one of:

- **VERIFIED**: a publicly documented vendor price, fetched on 2026-11-02, with the URL in the table.
- **ESTIMATE**: an explicit assumption, stated next to the number. Not a measurement.
- **UNVERIFIED**: a price that could not be confirmed. It has **no value** (null). The calculator never treats it as zero: any result that needs it lists it under `unverified`, sets `complete: false`, and omits that cost line, so the total is a **lower bound**.

Negative or non-finite inputs are rejected.

## How PayPal fees relate

PayPal's published US checkout merchant fee is 3.49% + $0.49 per transaction (fetched 2026-11-02; actual rates vary by account, volume, currency and agreement). That fee is charged by PayPal to the receiving merchant under the merchant's own PayPal agreement. In this model it is **not a PayFlow cost of goods** and is excluded from every cost and margin figure. It matters in three ways: (1) it is a cost the customer already bears, which is relevant to ROI conversations; (2) if PayFlow ever held funds or contracted with PayPal as a platform, who bears fees would need to be re-examined with counsel (not assessed here); (3) a per-action fee of one cent is small against a $0.49 fixed fee on each payment, which affects how a customer perceives the price. Today only PayPal Sandbox is used, which moves no real money and has no processing fees. `paypalMerchantFeeUsd` exists for informational use only.

These conclusions depend on the estimates in the table and could change by more than an order of magnitude once measured.

## Per active organization and per active agent

`costPerActiveOrganization` = variable cost of the org's operations + support time + an allocated share of platform fixed cost (Vercel Pro fee and Neon baseline compute). `costPerActiveAgent` divides that by active agents. Results for the illustrative tiers (see [GROSS-MARGIN.md](GROSS-MARGIN.md)): about $151 per month for the small tier ($50 per agent), $171 for mid-market ($4.26 per agent), $1,674 for enterprise ($4.19 per agent). **Support time is the largest line in every tier**; it is an ESTIMATE of human time, and whether it counts as cost of goods or operating expense is an accounting choice not made here. Platform fixed cost is about $39 per month before allocation ($20 Vercel plus about $19 Neon baseline if the database never suspends).

## Known limits

- Profile inputs are guesses; no benchmark on Vercel/Neon has been run.
- Region, plan tier and function memory size are undecided; the upper end of ranges is used.
- Free-tier credits (Vercel $20 credit, Neon, Pro flat-rate CDN) are ignored, so the model overstates small-scale cost.
- Excludes: payroll beyond the support placeholder, tax, payment of invoices, domain, GitHub/CI, security audits, legal, insurance, sales cost, any production rail cost.
- The model does not price abuse or free-tier fraud for SANDBOX/VERIFY.
